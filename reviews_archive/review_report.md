# カナバンク（バーチャルおこずかいシステム）テスト＆品質レビュー報告書

## 1. 総合評価・レビューサマリー（商用課金サービス視点）

| 評価項目 | 判定 | 商用化に向けた現状の障壁・コメント |
| :--- | :---: | :--- |
| **商用課金品質** | **不合格（要大幅改善）** | 有料SaaS/課金アプリとしての品質基準（データの永続性・親子間リアルタイム同期・セキュリティ）を満たしていない |
| **セキュリティ・認可** | **重大な欠陥あり** | URL・ハッシュの直接書き換えで子アカウントから保護者画面へ無制限にアクセス可能。認証が形骸化している |
| **データ同期・整合性** | **重大な欠陥あり** | 別端末同期不可（ブラウザローカル保存依存）。複数タブ間のイベント連動なし（リロード必須） |
| **UI/UX・レスポンシブ** | **要改善** | スマホ幅（幅390px以下）で保護者用ナビゲーションタブが画面外に見切れる（横スクロール表示欠落） |
| **バリデーション** | **要改善** | 減額・出金・目標金額で負数や非現実的な数値の入力制御、残高不足時の警告が不十分 |

## 2. 致命的不具合（Critical Bugs）

### 2.1 [SECURITY] 保護者画面への認可バイパス（子アカウントからの不正侵入）
- **現象**: 子どもアカウントでログイン中のブラウザであっても、URLに `#/parent` を入力するかブラウザの戻る/進む操作を行うだけで、保護者のダッシュボードへ何らパスワード再認証なしに遷移可能。
- **影響**: 子どもが自分でお手伝いを勝手に「承認」したり、お手伝い報酬単価を改ざんしたり、減額や出金記録を改ざん・消去できてしまう。家族向けおこづかい管理アプリとして致命的な設計破綻。
- **商用視点**: 課金して利用する親にとって「子どもに不正操作されないこと」は最優先要件であり、現状では製品として成立しない。

### 2.2 [SYNC] 別端末・クラウド間でのデータ非同期（完全ローカル依存）
- **現象**: トップ画面に「子ども用とお父さん・お母さん用でURLが分かれています。それぞれの端末でブックマーク・ホーム画面に追加してご利用ください」と案内があるにもかかわらず、データは各ブラウザの `localStorage`（`kanabank_data_v1`）にのみ保存されている。
- **影響**: 親のスマートフォンと子どものタブレット・スマートフォンなど、別端末からアクセスした場合、お互いの申請やお小遣い残高が一切共有されない。親端末からは子どもが申請した記録が見えず、子ども端末からは親が設定したお手伝いや残高が反映されない。
- **商用視点**: 案内文と実態が完全に乖離しており、課金ユーザーから即座に返金・クレームとなる最大要因。

### 2.3 [UX/SYNC] 同一ブラウザ内でのマルチタブリアルタイム更新の欠落
- **現象**: 同一端末・同一ブラウザで親画面と子画面を別タブで開いている場合でも、子どもが「お手伝い申請」を行った後に親画面を見ても申請件数が自動更新（バッジや一覧）されない。ブラウザを手動で「再読み込み（リロード）」して初めて反映される。
- **影響**: 親が画面を開きっぱなしにしている場合、子どもが申請したことに気づけない。承認後の残高反映も子ども側でリロードしなければ変化しない。

## 3. 機能・バリデーションの不具合および改善点

### 3.1 減額（叱られた）・出金（お小遣い使用）のバリデーション不備
- **残高のマイナス制限がない/仕様の曖昧さ**:
  - 親が過大な減額を入力した場合、残高が `0円` で下限クリップされるが、ユーザーに対して「残高を超える減額です」「0円以下にはなりません」といった注意文・確認モーダル等のフィードバックが一切ない。
  - 出金（お小遣い使用）で現在の残高（例: 500円）を超える金額（例: 600円、999,999円）を入力して「出金を反映する」を押下しても、残高チェックが行われずそのまま出金処理が通ってしまう。バーチャルお小遣いの残高管理として整合性が崩壊している。
- **入力値の異常系対策欠落**:
  - 金額入力フォームに負の値（`-100` など）を入力できてしまう場合があり、減額画面でマイナス値を入れると挙動が破綻するリスクがある。

### 3.2 モバイル表示（スマートフォン画面）のレイアウト崩れ
- **保護者用タブナビゲーションの見切れ**:
  - スマートフォンの標準的な横幅（375px〜390px）において、保護者ダッシュボード上部のナビゲーションボタン（`承認まち` / `減額（叱られた）` / `お小遣い使用` / `お手伝い設定` / `カレンダー`）が画面幅に収まらず、右端の「お手伝い設定」「カレンダー」が画面外に見切れる。
  - 横スクロールインジケーターや折り返しがなく、タッチ端末での操作性が著しく低下している。

### 3.3 目標設定機能の未成熟さ
- **達成時の体験・フローの欠如**:
  - 子ども側画面に「すきなおもちゃ・ゲーム（3000円）」等の目標設定があるが、残高が目標金額に達した際のお祝いアニメーション、および「目標のおもちゃを購入してお小遣い残高を消費・リセットする」連携フローが存在しない。
  - 目標金額に `0円` や現在の残高以下の金額を設定した際のエラーチェックがない。

### 3.4 お手伝いマスタ管理（親画面）の操作性
- **削除・編集時の確認フローの甘さ**:
  - お手伝いマスタの削除アイコンをクリックした際、誤タップ防止のための「本当に削除しますか？」という二重確認ダイアログ（Confirmation Modal）が省略されている。
  - 現在子どもが申請中のお手伝い項目を親側で削除した場合の整合性（参照不整合・孤児データの発生）が考慮されていない。

### 3.5 カレンダー画面の機能不足
- **日付選択・履歴閲覧の操作性**:
  - 日付をタップしても、当日のトランザクションが存在しない場合に「この日の記録はありません」といった空状態（Empty State）の視覚的フィードバックが乏しい。
  - 月を跨いだ集計（「今月のお手伝い合計金額」「今月減額された金額」）などのサマリー表示がなく、カレンダーとしての付加価値が極めて低い。

## 4. オンライン課金プロダクトとしての必須改善ロードマップ

もし本システムを「月額課金型SaaS」または「買い切り型ファミリーアプリ」として販売する場合、最低限以下の改修が必須となる。

1. **バックエンドDB・ユーザー認証基盤の導入（最優先）**:
   - Supabase / Firebase / 自前API等の導入により、世帯（Household）ID単位で家族をグルーピングし、マルチデバイス間での完全同期を実現する。
   - 保護者画面へは専用のPINコードまたは生体認証・パスワードによる強固なアクセス制限を実装する。
2. **WebSocket / SSEによるリアルタイム通知**:
   - 子どもがお手伝いを申請した瞬間、親の端末にプッシュ通知および画面バッジの即時反映を行う。
   - 親が承認した瞬間、子どもの画面にファンファーレや紙吹雪アニメーションが自動発火する双方向リアルタイム同期。
3. **入金・出金・ペナルティの財務整合性ガード**:
   - 残高を超える出金はブロック、または「残高が不足しています」と明示。
   - マイナス数値入力の排除、数値フォーマットの統一。
4. **レスポンシブUIの最適化**:
   - モバイルファーストのボトムナビゲーションバー（Bottom Navigation）への移行、またはタブのカルーセルスクロール対応。
